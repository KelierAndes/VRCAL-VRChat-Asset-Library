# Unity 输出读取与 AI 排障：实现与验收边界

记录日期：2026-10-24。用户新增需求：读取 Unity 输出，出现问题时在素材管理器内自动解释并给出解决步骤；尽量后台静默，避免手工复制 Console 内容。

状态：已实现独立的只读 Editor.log 监控、错误合并、诊断页面及千问／Kimi／DeepSeek 文本服务接入，并完成合成日志、模拟服务和原生 Electron 流程验收。工程助手的 Console／编译事件收集仍未实现。本轮没有读取用户真实工程日志，没有为诊断安装新助手，没有使用真实供应商 API Key 或调用收费 AI；实际 Unity 会话仍待隔离工程验证。操作步骤见[AI 使用说明](AI_BACKEND.md)。

## 当前只读实现与边界

- `UnityDiagnosticsMonitor` 每次读取先验证已登记的 Unity 工程，只有启动参数块中的 `-projectPath` 与所选工程一致，才返回该会话的问题。新的启动块、未知的新引擎初始化、截断和轮换都会重新核对，不把全局 Editor.log 直接分配给所有工程。
- 首次读取或需要重新确认归属时，从文件开头按 **256 KiB 块顺序扫描**全部会话／工程边界，上限为 **32 MiB、2 秒处理预算**。预算在分块读取之间及扫描结束时检查，不承诺能中断操作系统正在执行的文件读取。超过容量／处理预算返回 `unverified`，不展示未核实内容。不会用只读头尾的方式跳过中间可能存在的工程切换。
- 只有整次首次扫描完成，并且文件身份、长度及修改／变更时间在扫描前后保持一致，才发布结果；扫描期间变化会丢弃结果并等待重试。后续读取检查文件身份、头部和已读末尾的一致性，再增量读取；一次新增量超过 1 MiB 时重新进行上述完整核对。
- 首次扫描仅保留最后 **1 MiB** 范围内的诊断文本，历史部分只用于确认会话边界。内存最多保留 100 类问题，每条详情最多 4 KiB；超过 16 KiB 的单行整行丢弃，未写完的 UTF-8 行等待后续输入。超过 24 小时未更新的日志不作为新问题。
- 错误正文、堆栈和相对位置均经过常见凭据／个人信息过滤后才返回页面。其他工程的路径和报错不会出现在返回结果。自动分析按错误内容、堆栈、会话和 Unity 版本去重，重复次数、观察时间或仅新增警告不触发重复分析；AI 建议不执行命令或修改工程。
- 已覆盖超过 1 MiB 的启动扫描、中段切换工程、超出 32 MiB、处理超时、扫描中追加日志、跨块行、增量读取、截断、轮换、编译与异常归类、重复堆栈和脱敏。Windows 当前测试环境不允许创建文件符号链接，该分支仍依赖公共 `noLinks` 检查，不能把它记为实测通过。

## 已有基础

- `assets/unity/VRCALImportBridge.cs` 订阅素材包开始、完成、取消、失败事件，在工程 `Library/VRCALImportBridge` 下按请求 ID 回传结果及 Assets 路径。
- `assets/unity/VRCALMASetup.cs` 已回传 MA 等待选择、成功、跳过和失败信息。
- `src/main/project-import.ts` 会按工程、任务 ID 和源文件哈希核对回执，不能仅因收到一段报错文本就宣称对应导入失败或装配成功。
- 当前已经实现 Editor.log 增量读取，没有完整 Console 订阅或编译事件回传。Unity 启动采用忽略标准输出的方式，不能将“读取进程 stdout”当作已经具备的方案。

## 当前通道与后续扩展

1. **本轮已用：只读 Editor.log**。Windows 默认文件位于 `%LOCALAPPDATA%/Unity/Editor/Editor.log`，程序核实工程和会话后增量读取，处理截断和轮换。不确定归属时明确提示。当前没有任意自定义日志路径选择入口，不宣称所有启动配置均可识别。
2. **已有独立记录：导入／MA 回执**。继续按原有任务系统提供成功、失败等事实；本轮未将全部回执自动汇入 AI 诊断，也不根据日志时间接近推断错误必然由某次导入造成。
3. **后续候选：工程内 Console 助手**。可以通过 `Application.logMessageReceivedThreaded` 收集日志；若实现，回调需线程安全、只入有界队列，不在回调中调用不安全的 Unity API、写大文件或请求 AI。
4. **后续候选：编译事件回传**。可以通过 `CompilationPipeline.assemblyCompilationFinished` 取得编译器消息；本轮看到的编译错误来自日志，并非已经订阅此事件。

工程助手的安装／升级沿用原有显式工程操作及拥有文件校验，不借“查看日志”偷偷修改所有工程。读取系统日志不会修改 Unity 程序或源素材。

官方依据：

- [Unity 2022.3 日志位置](https://docs.unity3d.com/2022.3/Documentation/Manual/LogFiles.html)
- [日志回调及线程限制](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/Application-logMessageReceivedThreaded.html)
- [编译结束事件与编译器消息](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/Compilation.CompilationPipeline-assemblyCompilationFinished.html)

## 用户看见的流程

- 报错页选择已登记工程，打开此页时每 5 秒检查所选工程，也可立即检查。没有工程或没有可核对日志时说明原因，不抢焦点或逐条弹窗；不是所有工程的常驻后台扫描。
- 相同错误合并次数，错误和警告分别显示。不把时间接近当作因果证据；本轮没有自动识别“某次导入导致”的归因功能。
- 开启自动诊断后，新错误短暂稳定再合并分析，避免逐行调用。页面按错误内容、会话和版本去重；服务缓存包含脱敏输入、模型、服务商和提示词版本，变化后允许重评。
- 结果展示中文摘要、已观察到的事实、可能原因、处理步骤、如何验证和缺少的信息；可展开本地脱敏错误记录。本轮没有依据 AI 结果自动打开源码、改脚本或执行命令的入口。
- 同一应用会话返回页面会恢复相同分析的建议，重启后可由服务缓存复用。忙碌、限流或取消最多间隔 30 秒重排 3 次；普通失败不自动循环重试，必要时由用户明确重试。
- AI 推测明确标记。当前读取范围没有错误不等于工程已修复，仍须在 Unity 中重新执行原操作。涉及工程修改的建议提醒先备份；AI 文本不获得修改权限。

## 与 AI 分类共用配置

复用 [AI 分类实现](AI_CLASSIFICATION_NOTES.md) 中已经接入的千问、Kimi、DeepSeek、系统加密密钥、次数控制、缓存与暂停机制，不要求用户为每个功能重复填密钥。分类和诊断分别选择范围，并在首次启用对应处理前确认说明；之后在用户选择的范围内自动处理，不逐条重新征求同意。默认每天共用 20 次，限请求次数而非金额，服务商实际收费按账号规则。

本轮仅使用文字。契约支持短版本字段，当前采集可核对 Unity 版本；未从工程证明的 SDK／MA 版本不会编造后发送，也没有上传整个依赖清单。输出不包含自动可执行命令或模型生成链接的执行通道；应按实际版本核对建议，不能把文字中的说法当作官方依据。

本地规则先识别明确错误模式并提供基础解释，AI 不可用时仍能查看原始错误和已有建议。模型拒绝、超时、断网或额度不足不改变导入状态，不阻塞工程工作。

## 数据与安全

- 本地采集仅处理所选工程可核对的近期输出；云端 AI 默认关闭。启用后只发送筛选的错误摘要和必要短版本号，不整份上传 Editor.log、源码、场景、素材或其他工程。
- 上传前过滤账号、令牌、Cookie、邮箱、用户名、完整个人路径及 URL 等信息，并去除堆栈和常见源码行，最多 20 行、总计 6000 字符。页面上的脱敏错误记录发送前还会筛选限长，不逐字上传全部详情。过滤无法保证涵盖任意插件输出，可关闭 AI 而保留本地查看。
- 日志和商品说明都是不可信输入，出现“忽略规则、执行命令、上传密钥”等文本只能当作日志数据。AI 结果仅按受限制的数据格式解析，不能作为执行指令。
- 给采集速率、单条文本、累计容量和保留期限设上限；重复错误计数而非无限堆积。主进程验证工程路径、会话、消息大小，远程 AI／网页均不获得本地文件接口。
- 本轮已经更新协议／隐私说明，明确用户启用后由所选官方服务商处理文字。独立 AI 建议、密钥、设置与调用计数不随普通备份导出，同机迁移会携带。说明更新不是对默认上传的授权，未启用／未同意时不会发送。

## 已有验收证据

原生 Electron 的 AI 整体验收共 10 组通过，其中诊断部分使用合成 `CS0246`、`NullReferenceException` 日志和模拟供应商。确认所选工程错误进入请求时不含私人路径或堆栈，能够显示建议；离开再返回复用同一建议，不新增供应商请求。实际 Windows 系统加密、重启、普通备份排除凭据及诊断缓存、同机迁移保留密钥与缓存也已验证，合成日志源哈希未改变。

本次工作区记录为 `work/ui-ai-tools-9d6pcT/report.json`，明确标注合成测试及未付费。四主题与 980 像素窗口、200% 缩放下的页面仍可滚动查看。以上没有启动真实用户工程，不能当作真实 Console 事件接入或真实模型排障准确率证明。

## 验收重点

- 导入失败、MA 失败、脚本编译错误、异常堆栈、一般警告；不同工程同时打开。
- 工程原本就有错误、首次助手编译失败、域重载、日志轮换／截断、Unity 退出、旧日志遗留。
- 中文／日文路径、长堆栈、重复刷屏、损坏回执、错误的工程／任务关联。
- 脱敏、预算、去重、取消、网络失败、无 AI 密钥时的本地查看、模型不确定与恶意日志指令。
- 实际 Unity 隔离工程验证仍需完成；仅有 TypeScript／合成日志测试不能宣称已接通 Unity Console。
