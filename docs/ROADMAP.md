## 社区可以继续参与的工作

下面是可讨论和认领的方向，尚未承诺完成时间。开始较大改动前先提 Issue 明确范围，避免重复工作。

| 方向 | 可以贡献的内容 | 验收重点 |
| --- | --- | --- |
| 素材扫描范围管理 | 改善范围提示、路径冲突说明与子目录排除体验 | 仅改变索引范围；不删除素材，保留人工标注，明确旧记录怎样显示 |
| 匹配与分类样例 | 公开商品链接、异常文件名、精简网页样例与离线测试 | 编号、作者与本商品名称相互核对；有歧义时不自动认定 |
| 贡献者入门 | 文档、安装说明、脱敏截图、常见问题 | 新用户能照着步骤完成；不要求接触个人资料库 |
| 界面与可访问性 | 键盘操作、缩放、窄窗口、对比度和文案 | 四主题、980px、200% 缩放下主要操作可用 |
| 多语言 | 校对简体中文、日语与英语，补充缺失翻译与长文字样例 | 保留素材原名与人工标注，三种语言下主要操作清楚可用 |
| 回归与兼容 | 中文／日文／表情路径、目录合并、备份与来源撤回 | 合成输入前后清单与哈希一致，人工信息重启后保留 |

文案、文档链接和已明确复现步骤的小问题可标为 `good first issue`。复杂目录合并、迁移及账号安全问题需要先熟悉相应模块，不宜仅凭任务看起来短就认定为新手任务。

## 商品语义搜索：参考 AstroLens，尚未实现

[AstroLens 官方介绍](https://www.astrolens.dev/about/)描述了以合作的世界资料为基础，整理公开说明并按含义／氛围的接近程度检索。这里借鉴检索与交互思路，不使用其合作数据库，也未接入该站的服务或接口。此次公开检查未找到可供商品搜索复用的公开 API 文档。

我们目前的 ProductDiscovery 仍是“需求 → 本地规则或 AI 整理检索词 → 网站真实商品卡片 → 标题命中排序”，不能将其称为已经完成的商品语义检索。下一阶段候选方案：

1. 将品类、风格、颜色、排除条件和适配角色分开呈现，允许修改；区分硬条件、偏好与证据不足的要求。
2. 从用户已有资料和合规可取得的真实商品元数据建立有来源、更新时间的索引；不承诺覆盖全站，不把 AI 生成的商品名作为已存在商品。
3. 多组日文／英文／中文词召回后去重，再评估本地多语义表示或自选 AI 排序；须与当前标题命中排序做真实样例对照。
4. 每张卡片说明命中了哪些条件、有哪些缺失；角色名出现不等于已证实适配，颜色／风格推断不能冒充作者说明。
5. 支持“不要露肩”“保留哥特，换成旗袍”等继续修改，保留原条件；同时标明本地已有、云端登记或尚未下载，减少重复寻找。

验收应包含中日英描述、否定条件、同名不同作者、适配证据缺失、无法找到的要求、旧索引与断网回退。模型、数据取得方式、更新成本和授权边界仍需核实；没有公开说明模型或向量库，不能将对该站内部实现的猜测当作已知事实。
