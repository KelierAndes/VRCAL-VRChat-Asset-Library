VRChat本地素材管理器 v1.4.0-preview.11

本轮让同目录的同名图片成为素材包的本地封面，减少包和封面各占一张卡片的情况；同时加固应用资料库、备份和任务记录的写入边界。

文件名称与位置保持原样。 本轮已用合成素材核对重复扫描前后的名称、路径、大小、修改时间和内容哈希不变，并修正有条件的硬链覆盖与目录边界缺口。普通扫描直接改名或移动原文件的情况尚未复现；封面修复和这些加固不能作为实际磁盘变化已经定位或解决的证明，也不能据此把反馈解释为仅界面排序。

同名图片如何成为封面

在同一已授权目录内，ZIP、RAR、7z、Unitypackage 可以使用精确同名的 PNG、JPG、JPEG、WebP、GIF、BMP 作本地封面。例如 鸭鸭.rar 与 鸭鸭.png 配对；鸭鸭.rar.png 也可对应完整包文件名。

名称比较支持 Unicode NFKC 与大小写归一，但归一后出现不同包名冲突时拒绝猜测。版本和适配名属于名称的一部分：鸭鸭_v2_Airi.png 不会套到 鸭鸭_v1_Moe.rar。明确以空格、下划线、连字符或点分隔的封面后缀也可识别，例如 鸭鸭_cover.png、鸭鸭-封面.jpg；不会仅凭目录里有一张通用 cover.png 就分给所有包。

手动添加单个文件不查父目录；同次明确选择包与图片可配。完整「刷新素材」时，如果同目录的包和图片两个精确文件路径都已分别登记为手动文件来源，也可在这个已授权集合内配对，不要求当初必须同一次添加。配对不跨目录，也不扩大原扫描授权。

人工封面优先于商品封面，商品封面优先于本地预览。新规则只补充本地预览，不确认商品来源，也不把图片加入 Unity 导入成员。独立图片和贴图仍按原有目录识别规则保留。详细示例见扫描与封面指南。

旧图片记录怎样处理

升级后点击一次 刷新素材。成功作为包封面的新配对图片不再单独建卡；旧的无人工资料配对图片退出商品列表与匹配队列，但原记录编号和备份仍保留，也不会挤进用户的「已隐藏素材」列表。原包和图片留在原处，不合并文件、不删除图片、不改包内容。

有人工标题、备注、标签、收藏、手动封面、分类、来源、排除等信息，或被集合、关联记录引用的旧图片，继续保留卡片，避免藏起已有资料。旧图仍然可见时，先检查这些记录，不需要为减少一张卡片而清除自己的标注。

素材与应用资料库要分开

素材目录是你保存包、模型和图片的位置；应用资料库保存索引、标注、封面缓存、设置和会话数据，备份保存可恢复的资料库记录。素材目录与资料库／备份位置不能相同，也不能互相包含；将素材目录放进资料库或把备份放进扫描目录都会被拒绝。

保存过程使用独占创建的随机临时文件，并核对文件身份，拒绝多硬链文件，失败清理也只处理本次拥有的临时文件。队列、资料库位置记录与百度任务保存同步加固。这是针对已复现条件的保护，不能推导为所有文件系统竞态都已消除。

如果遇到目录重叠提示，先保留原素材和资料库，核对设置中两类路径。不要为通过检查删除其中一份，也不要把资料库整体登记为素材目录。指南有独立目录示例。

升级与反馈

  1. 先备份资料库，退出旧程序，再运行 VRC-Asset-Library-1.4.0-preview.11-x64.exe。程序、对应源码与验收记录见 Releases 对应版本。公开预览需手动下载，不进入稳定版内置更新通道。
  2. 继续使用原资料库；若询问保存位置，选择原 VRChatAssetLibrary 文件夹的上级目录，避免创建另一个空库。
  3. 点击一次 刷新素材，检查包封面、旧图片的人工资料及独立图片。无需重新确认已有商品来源。
  4. 若实际磁盘文件名或位置再次变化，先保留变化前后完整路径、当时版本、执行的操作和脱敏截图。不要用反复扫描、重新命名或搬动文件覆盖这些线索；反馈时不上传付费素材、账号凭证或整份个人资料库。

本轮最终自动化、打包、CI、源码与附件摘要结果以对应验收记录为准，这里不沿用旧版通过数字。合成夹具证明所述条件下的行为，不代表已定位用户此次磁盘变化。
