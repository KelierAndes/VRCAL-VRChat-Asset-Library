# VRChat本地素材管理器 1.2.0：工程与云端功能

本版汇总 1.2.0-local.1–local.7 的本地改进，随 1.2.0 正式版公开发布。百度网盘网页目录读取仍标为试验功能，受官方网页结构与登录验证影响。原有本地扫描、BOOTH 补全、人工标注和工程导入继续保留。

## 读取工程内商品

在“工程与成品”中选择工程，点击详情里的 **读取工程内商品**；也可以右键工程卡片或从“查看工程文件”进入。读取目标工程的 Assets，显示商品／素材卡片、封面、工程路径和识别依据。即使素材以前由 Unity 直接导入、原 ZIP 不在资料库，也能读取其目录和预制件线索。

识别使用名称中的 BOOTH 编号、预制件／模型名称、有限的 README／说明／Booth.url 链接、已完成导入的准确路径和已有资料库。编号相符的已有商品可复用封面；仅同名、多个来源或说明中的参考链接会保留为待核对线索。辅助目录、目录链接、缓存、嵌套工程和单独存放的 ZIP／Unitypackage 不当作已导入商品。

对新条目点击 **登记并匹配**，或选择显示项后批量登记（每批最多 100 项）。联网开启时加入现有 BOOTH 队列，沿用请求间隔、缓存、暂停、重试和限流；离线时先登记，之后开启联网补全。商品资料和工程关联保存在当前 SQLite 资料库，重启、迁移与普通备份恢复沿用现有机制。登记的条目也会出现在素材库，分组为“工程内商品 · 工程名”。

展开 **BOOTH 搜索与手动来源** 可修改检索词、打开内置搜索或粘贴商品网址／1–12 位合法 ID。找到商品后仍使用“应用此商品”，来源支持原有撤回。名称线索不会直接覆盖另一个库内商品的来源。封面来自已匹配的资料库或联网补全，尚未匹配时显示占位。

卡片路径可以复制、定位或右键操作。“查看库内详情”可进入已有素材详情并返回工程。只有手动关联而未找到文件依据的条目会明确标出；本功能列出已导入 Assets 的内容，不判断当前场景／角色是否正在使用，也不能据此判断购买权限。

单次最多检查 60,000 项、20 层或 8 秒，卡片最多显示 1,000 项；说明仅按文件名白名单读取，每份最多 128 KiB、共最多 100 份／2 MiB；到达边界会提示。列表更新复用已读的目录清单，点击“刷新读取”才重新读盘。搜索时仅发送商品名称、编号和来源 URL，不发送工程路径、文件正文或私人备注。原工程与原素材保持只读。

## Unity MA 助手中文界面

截图中的独立 Unity MA 装配助手现在提供中文标题、按钮、字段、装配说明、状态和常见错误提示。角色名、材质／素材名称、预制件路径和作者预设保持原样，未知第三方诊断保留原始文本以便排查。

新导入会安装中文助手。已有工程请在管理器中打开该工程的“工程导入记录”，点击 **更新 MA 中文界面**，切回 Unity，等待编译完成后重新打开 MA 窗口；无需重新导入素材。可使用中文菜单 **Tools → VRC 素材库 → 装配导入的预制件**，原英文菜单仍可使用。

更新只替换字节完全符合已知发行版本的自带助手，保留 `.meta`、导入文件、场景、人工标注与请求记录。工程中存在自定义助手时会拒绝覆盖；有导入任务正在进行时请等待结束。替换脚本会触发 Unity 正常编译与重载；先前已经启用的待处理 MA 请求沿用原规则，不会因界面汉化重新执行已结束的请求。

## 导入后的 Assets 位置

打开目标工程的“工程素材文件”或“导入本地素材”，下方“工程导入记录”中显示 Unity 返回的位置。新版导入前另存一份文件元数据清单，完成后自动对比 Assets 的新增文件、修改文件及新增目录，显示“工程变化候选位置”。每条可复制 Assets 路径、定位，也支持右键菜单；重启后结果保留。清单只读文件名、大小和时间，不修改素材。

旧记录没有导入前清单时，点击“查找新增／修改位置”，按导入起止时段查找近期修改文件，最多取最后 24 小时，显示为“近期修改”。文件修改时间保留为旧日期、相同内容再次导入或文件已移走时，可能没有线索。候选可能包含同期手动编辑，仅用于核对位置，不会加入精确导入回执，也不会触发自动 MA 装配。

扫描限定目标工程 Assets，跳过 .meta、目录链接和 VRCAL 助手。单次最多检查 100,000 项或 20 秒，候选保留最多 1,000 条／128 KiB；达到边界会显示不完整。导入前清单临时放在所选资料库的 project-import-baselines，最终候选写入 project-imports.json。不会按列表轮询反复扫描工程。

如果出现“导入完成”但 MA 仍保留较早的包导入失败信息，可点击“重试 MA 配置”，再在 Unity 中继续处理。只在存在同一次成功导入回执、且没有不明装配过程时恢复 MA 请求，旧失败回执保留；不会重新导入素材，也不会自动保存场景。真实的 MA 依赖错误或装配中断仍需在 Unity 中核对。

## 百度网盘：母目录与子目录读取

“目标文件夹”就是网盘网页里当前打开的文件夹。打开“百度网盘与云端素材 → 打开百度网页登录”，正常登录后进入要整理的母目录，点击 **读取此文件夹及所有子文件夹**。只遍历所选范围，不会转去其他母目录。资料库位置和登录会话继续使用此前选择的位置。

程序会串行打开子目录并滚动读取列表，按文件名记录 ZIP、RAR、7z、Unitypackage 等条目，不下载、不解压、不移动或删除网盘内容。任务显示范围、当前目录、已读目录、文件数和待处理数量；“暂停读取”“继续读取”“停止读取”可控制任务。请先暂停，再手动切换网页目录。任务进度单独保存在资料库的 baidu-directory-task.json，重启后从暂停状态继续；更换账号不能接着读取另一账号的任务。

个别目录失败时，其他目录继续；展开失败列表后可重试。遇到验证或账号/页面变化时会中断。网页登录、网络波动、未知列表、独立分页或超大目录仍可能阻止读取，程序会保留已读记录，并不会把未读到的文件当作缺失。单目录最多保留 5,000 个索引条目，资料库合计最多 2,000 个目录、50,000 条云端记录；到达边界会保留现有资料并停止或提示失败。

普通的“读取当前文件夹”按钮只记录当前可见部分，可用于快速试读。新版已适配实际登录页面的完整 data-title 文件名、显示类型、无路径参数的根目录，以及深层面包屑省略和文件名前后空格；不把网页上四舍五入的大小当作精确字节。

本地素材扫描本来就支持递归：在设置添加本地母目录即可，不需要逐个添加子目录。原压缩包不会自动解压。

### 云端和本地标记

- “云端与本地”：当前索引与一个可用本地素材的商品编号唯一对应，或文件名及正数大小唯一一致，也可由你手动关联。
- “仅云端记录”：已读取云端条目，但尚无可用的本地对应物。
- “关联待确认”：存在多个本地候选，需要手动选择。

这些标记代表存放线索，不能保证本地和云端的版本、适配或二进制内容相同。不同版本、多个编号或日期不会自动认定。选择“关联本地素材”可手动绑定、“保持独立”可排除自动关联，“恢复自动关联”可撤销这项人工决定。

离线仍能浏览已保存索引。再次读取部分页面会保留以前未显示的条目，并保留各条目上次看到的时间。移除索引只清除本地记录与关联，不删除网盘文件。

登录会话保存在所选资料库的 baidu-session；迁移时使用同一应用会话的系统加密快照。普通整理备份只含云端目录信息与关联，不含登录凭证。退出百度账号会清除本应用的会话，已读取索引保留。不导入其他浏览器 Cookie。

本功能不使用 AI，不调用非公开网盘接口。远程网页没有桌面接口、素材目录或 Node 访问能力。

## 导入后用 MA 装配到角色

素材右键“导入到工程”，选择源文件和目标工程。在预览中勾选“导入后用 MA 装配到角色”，再执行导入。此项默认关闭，需要目标工程已安装 MA 与 VRChat SDK。

Unitypackage 仍由 Unity 原生窗口确认导入项；普通文件复制到新的 Assets/VRCAL_Imports 目录。文件真正导入完成后，助手处理本批 Prefab。完整明确的批次清单中只有一个 Prefab、当前打开场景只有一个有效角色时自动装配；有多个角色或 Prefab 时，装配前显示选择窗口。没有打开角色场景、缺插件或无法确认清单时保留待处理提示，不猜选。

装配后的 Prefab 实例直接放在所选角色下面，并排在子物体最底部，不再套一层素材库分组。兼容衣装调用 MA 官方 Setup Outfit，核对 Merge Armature 绑定到所选角色；已有合法的 MA Merge Armature/Bone Proxy 预设保留。普通不兼容 Prefab 不会只靠改父物体就显示装配成功。

本模式不会新建游戏内圆盘菜单开关。原有“导入后配置 MA 菜单”作为另一种可选模式保留，两种模式互斥；作者随 Prefab 提供的预设不会擅自删除。

场景修改可用 Unity Undo 整组撤回，不自动保存。源 Prefab、原菜单和参数资产保持原样。角色/素材适配、骨架、比例和穿模仍需在 Unity 中检查；本功能不保证任意商品跨角色自动适配。

关闭窗口后，可从 Unity 菜单 Tools → VRC Asset Library → Assemble imported Prefab 再次打开。旧菜单入口 Configure imported MA menu 也保留。助手冲突时保留原文件，修正后可在应用导入记录点“重试 MA 配置”，不会重复复制素材。自有旧助手仅在与随包旧版字节完全一致时安全升级，Unity 的 .meta 不变，未知自定义助手不覆盖。

## 在应用内查看导入后的 Assets 位置

导入记录中显示“导入后的 Assets 位置”，支持“定位导入位置”和“复制 Assets 路径”，并可展开查看已返回的具体文件。

- 普通复制：显示本次实际的 Assets/VRCAL_Imports/... 目标，不用原素材路径冒充导入位置。
- Unitypackage：使用 Unity 实际完成回调提供的本批 Assets/... 路径，可分布在多个目录。不会假定包名就是导入目录。
- MA 装配：另显示使用的 Prefab 资产路径及角色层级路径，例如 AvatarName/Dress。

正在导入、失败或取消的任务不会把计划路径显示为实际导入位置。Unity 未提供位置时明确显示未知；较大批次只保留部分路径并显示提示，未列出的文件不代表未导入。文件移动或删除后定位会提示，不会打开其他位置。重启会保留导入位置与装配结果。

文件导入和 MA 装配有独立状态：文件导入完成不等于已装配到角色。回执与导入编号/哈希绑定，防止错误回执和重复装配。

助手位置为 Assets/VRCALMASetup/Editor 与 Assets/VRCALImportBridge/Editor；通信位于 Library/VRCALImportBridge。

## 构建源码

Windows x64，Node.js 24 或相容版本。源码目录执行 npm ci，再执行 npm run build；运行 npm run dev。打包使用 npm run package。Unity 助手源文件随 assets/unity 提供，不打包 MA/SDK 二进制。

## 更新记录

侧栏点击“更新记录”，或打开“设置与备份 → 应用更新 → 查看更新记录”。页面随程序保存，断网可用；支持按版本、功能关键词及正式版／本地试验版筛选，并显示当前运行版本。历史本地试验条目仅记录开发过程，对应试验程序未单独公开发布。

后续维护时，在 `src/shared/release-notes.ts` 顶部追加版本条目，保持日期从新到旧；翻译集中在 `src/shared/messages-releases.ts`，同时更新 `CHANGELOG.md`。当前运行版本来自应用本地状态，与记录排列顺序无关。


正式更新同时记录在 [GitHub Releases](https://github.com/NecoAya/VRCAL-VRChat-Asset-Library/releases)、[CHANGELOG.md](../CHANGELOG.md) 和应用内。内置更新以最新正式 Release 为准，维护流程见 [发布说明](RELEASING.md)。
