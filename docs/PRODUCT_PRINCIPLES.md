# 产品原则：尽量自动，尽量少操作

维护者于 2026-10-24 明确：能在后台静默完成，就在后台完成；能让新手直接使用，就不要让用户理解内部步骤。非必要不增加点击、填写、复制链接、切换窗口或重复确认。

## 日常操作

- 用户完成首次必要授权、登录和保存位置选择后，复用有效选择。不要每次启动、检查或下载都重新走设置流程。
- 正常后台工作不弹窗、不抢焦点、不自动打开可见浏览器。应用内保留状态、进度、结果和停止入口；新交付用侧栏蓝点提示。
- 可以可靠推断的链接、提取码、分类和关联自动处理；确有歧义时集中列入待核对。没有可靠依据的内容不能为了少点击而猜测为正确。
- 一次明确操作应完成连续步骤。例如点交付链接后直接读取文件列表；首次下载缺少保存目录时提示选择，选好继续原下载，以后复用该目录。
- 登录失效、验证码、缺少目录、提取码冲突等需要本人处理的问题，显示具体下一步。可重试的短暂网络错误按退避规则处理，不连续弹窗。
- 不自动扩大授权范围。删除原文件、覆盖文件、账号验证等必要控制保留；关闭功能后停止，不偷偷恢复。

## 待下载链接的目标流程

1. 首次启用时说明读取范围；直接选择后台模式应一次覆盖相应授权，不要求先开启前台模式再追加一次确认。
2. 登录有效且应用运行时，自动检查近期交付，提取分享链接和提取码，按账号去重并更新蓝点。默认最近 24 小时，时间不明待核对。
3. 点击记录直接读取文件列表，无冲突时不再要求点击第二次“读取分享文件”。用户选择具体下载内容，进度和完成位置留在应用内。
4. 自动下单、支付、发送消息，以及未经明确选择就批量下载大文件，不因“后台静默”而自行引入。静默是减少打扰，不是网站侧不可见；打开会话仍可能改变平台已读状态。
5. 程序退出后不承诺继续检查；需要托盘常驻或系统自启时另行说明，不偷偷安装后台服务。

这是产品目标和评审标准，不是功能完成声明。真实账号读取器及后台发现仍须完成登录页面验证，未实现时明确说明。

## 评审时核对

- 正常路径需要点几次？其中有没有只为实现方便增加的步骤？
- 已经选择或授权的信息是否被重复询问？取消操作是否真的停止？
- 失败后是否保留当前进度，能否从原处继续？
- 后台工作是否不抢焦点，用户是否看得见结果并能暂停？
- 是否把未经实现／验证的自动化当作已可用功能介绍？
