# 同名封面扫描与源文件写入保护 Implementation Plan

> 执行方式：当前隔离工作区内并行实现各自独占文件，统一编译与验收；遵循 systematic-debugging、test-driven-development、verification-before-completion。

**Goal:** 同目录压缩包与同名图片显示为有本地封面的素材；保留独立图片和历史人工信息，补齐已证实的写入边界。

**Architecture:** 在扫描已授权目录的一次枚举中计算配对，不对单个显式文件扩大读取范围。封面复制到内容哈希缓存；原素材不改名、不移动、不解压到源目录。历史无人工资料的图片记录用内部扫描标记退出商品列表与匹配队列，原ID与备份记录保留；带人工资料、来源或集合／关联的旧图保留可访问入口。写入使用独占临时文件并核对归属，素材与资料库／备份双向隔离。

**Tech Stack:** TypeScript、Node fs／SQLite、Electron、现有 Playwright 隔离验收。

**Spec:** 用户本轮两张反馈截图及补充“文件位置或名称也变了”。同名图片误入库已由代码确认；普通文件真实改名／移动尚未复现，不能把条件性缺口当作本次原因，也不能当作只是UI排序。

## Global Constraints

- 不访问或修改用户真实素材、工程、登录会话；测试只用隔离合成文件。
- 不自动整理、移动、改名或解压源文件。
- 精确保留版本号、作者、适配名和目录边界，歧义不跨商品配图。
- 普通图片／贴图、显式单图添加和人工资料继续保留。
- 不将封面加入普通导入成员，避免“只导入封面”。
- 先中文，按现有规则同步GitHub、匹配源码、说明与预览程序。

## Review Focus

1. 多个不同包名经Unicode归一后碰撞，应拒绝歧义。
2. 单个包的手动添加不能扫描未授权父目录寻找图片。
3. 旧图片的标注、集合、关联、人工来源与撤回恢复不能丢失。
4. 扫描取消、图片无法缓存、素材消失时不能产生孤立隐藏。
5. 双向目录嵌套、目录链接和硬链接不能绕过写入保护；失败清理不能删掉不属于本次操作的文件。

## Tasks

- [x] 历史记录：Store内部扫描标记、动态人工信息保护、备份恢复、取消配对与匹配队列回归。
