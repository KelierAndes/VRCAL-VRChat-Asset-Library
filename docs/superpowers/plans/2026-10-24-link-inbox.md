# 近期待下载链接

## Goal
登录后从已打开页面及后台检查发现近期交付链接，汇入原生页面，由用户选择下载。默认最近 24 小时，可缩短为 6 或 12 小时；不是整段历史回收。

## Architecture / Tech Stack
现有 Electron 沙盒官方网页登录会话 + 有边界的只读页面适配器；独立加密本地收件箱；React 原生列表；复用百度分享解析、原生下载和 BOOTH 下载处理。新增中文文案，暂缓整体翻译。

## Spec / Global Constraints
- 2026-10-24 用户补充的产品宗旨：后台静默、新手直接使用、非必要不增加操作。完整约定见 `docs/PRODUCT_PRINCIPLES.md`，贡献指南已引用。首次必要授权后复用选择，正常状态在应用内反馈，不抢焦点；需要本人决定时才提示。
- 用户要求前台识别及后台发现未打开会话。后台每 3 分钟串行检查，关闭联网、暂停、验证或退出时停止。账号未登录不能识别。
- 前台识别和后台检查默认关闭；主进程分别确认并记录说明版本、时间和范围。缺少当前有效同意时，保留旧记录但不恢复识别。
- 不调用私有接口，不抓其他应用流量，不发消息、不下单。远程网页不获得桌面接口。
- 来源时间与发现时间分开。无可靠来源时间只列入待核对，不亮蓝点；超过范围的历史记录不新增。下载记录保留。
- 同平台/账号/规范链接去重，提取码冲突需核对；重复轮询不重置已读/忽略状态。
- 原素材及实际资料库只读，测试使用独立资料库；不使用 IDM。
- 私人分享链接/提取码仅在所选资料库加密保存；普通备份不含收件箱，迁移保留。网页结构和后台兼容性必须用真实登录页面验证，未经验证不得宣称可用。

## Tasks
1. 纯逻辑与存储：`src/shared/link-inbox.ts`、`src/main/link-inbox-store.ts`。先测时间边界、多链接提取码关联、重复/冲突、加密重启和坏文件保留，再实现。
2. 只读平台观察：登录隔离测试窗口后核实消息/订单容器、账号、时间及导航结构，新增适配器和后台串行调度。未验证结构停止并显示原因，不猜测账号或时间。
3. 固定 IPC 与原生页面：侧栏待下载链接、蓝点、时间筛选、暂停/检查、已读/忽略、选择读取百度链接；复用下载进度，BOOTH 走官方已购下载流程。
4. 隔离 UI/持久化测试、下载状态关联、离线/限流/账号退出、980px 和 200% 缩放；真实登录验证成功后才标记对应平台自动识别可用。

## Interfaces
`InboxObservation {platform,accountKey,sourceKey,sourceUrl,title,sourceAt?,text,boothDownloadPage?}` 只在主进程间传递；网页文本不得成为程序指令。`inboxState/configureInbox/openInboxAccount/checkInbox/markInbox/readInboxLink/clearInbox/clearInboxAccount` 是渲染进程唯一入口，不提供任意执行或下载 URL 接口。

## Review Focus
时间缺失及昨天跨午夜；一个消息多个分享/多个提取码；非会话页面/推荐商品误入；账号切换；注销/暂停后的在途回调；坏加密文件覆盖；备份泄露；下载失败被误标完成；界面蓝点与已读状态一致。
