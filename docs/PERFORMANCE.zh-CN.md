# 启动速度与内存：怎样测、怎样选择程序包

## 这次优化了什么

- 启动素材库时不提前加载完整网页解析器。首次解析 BOOTH、闲鱼或百度页面时，再加载原来的 Cheerio；解析实现和结果保持。
- 没有云端文件时，列表和详情不再为了云端关联而复制、遍历本地全库。已经登记云端文件的匹配行为保持。
- 提供可完整解压后运行的程序 ZIP，减少单文件 EXE 每次启动展开程序的开销。

这两处代码优化针对可验证的重复工作。网页首次解析会承担延后的加载成本；不会将模块微基准的节省直接当作整个应用的节省。

## 两种程序包

`VRC-Asset-Library-版本-x64.exe` 是单文件便携启动器。双击即可运行；它需要先在临时位置展开程序，退出后清理临时程序文件。保留现有受校验的单文件更新方式。

`VRC-Asset-Library-版本-x64-Folder.zip` 是完整解压运行包。右键解压全部内容，进入目录，运行 `VRC素材库.exe`。以后直接运行这个文件，可为它创建快捷方式。程序需要同目录 DLL、resources 等文件，不能只把里面的 EXE 单独拿走，也不要直接在压缩包预览中运行。

解压目录运行当前不支持应用内自动替换，需要从官方发布页手动更新。公开预览版本本身不进入稳定自动更新通道。本次保留更新器的原有验证和替换边界。

## 升级与资料库

升级前正常退出旧版，再启动选定的新版本。继续使用原资料库；不要为测速删除资料库、封面或系统缓存。程序包与素材目录、资料库分别存放。手动换程序目录不会替你迁移素材。

## 实测口径

基准脚本是 `scripts/benchmark-startup.cjs`，只创建隔离资料库，不打开用户账号、素材或 Unity 工程。

- 环境为本次 Windows 11 电脑，Intel Core i9-13900H、约 32 GiB 内存；其他程序保持运行，系统负载会影响结果。
- 预置 300 条合成索引，每条含 1035 字符合成说明；没有封面、云端文件、实际压缩包扫描、联网、下载或 3D。首屏显示 100 张卡片。合成源文件前后清单与 SHA-256 一致。
- 每种程序包启动 4 次：第 1 次使用新的浏览器配置；后 3 次重复使用该隔离配置，重新创建整个程序进程。没有清空 Windows 文件缓存，因此不称为操作系统冷启动。
- 从创建程序进程计时，直到素材卡片可见、加载完成，并经过两帧绘制。包含隔离测试连接和轮询开销，不是无测量工具的点击到首帧；单文件展开耗时计入，退出清理不计入。
- 首次与再次启动分别保留；再次启动报告后 3 次中位数。内存取每次界面就绪后等待 8 秒的采样，报告全部 4 次中位数。
- 内存统计整棵本次启动的进程树，包括启动器、主进程、界面、GPU 与辅助进程。使用 Windows `WorkingSetPrivate` 的私有驻留量，另列 `PrivateBytes` 私有提交量；不能把含共享页的工作集相加当作独占物理内存。
- 不强制回收 JS 堆、不关闭 GPU、不最小化测试窗口。1 MiB = 1,048,576 字节。网页、封面、3D、大资料库和系统内存压力都会改变实际占用。

## 已测基线与本版结果

同机 preview.12 的单文件包再次启动中位数为 **7.570 秒**，新浏览器配置启动为 **8.313 秒**；解压目录分别为 **0.755 秒**和 **0.909 秒**。私有驻留内存四次中位数分别约 **159.3 MiB**、**158.5 MiB**。这是上述隔离条件的结果。

preview.13 的最终对照、各次样本及提交内存见同版附件 `Performance-1.4.0-preview.13.json` 和验收记录。保留波动和具体条件，不将微基准或单次最好值当作固定承诺。
