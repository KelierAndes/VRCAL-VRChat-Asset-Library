# 维护应用内的赞助者名单

应用在“贡献者与社区”的代码贡献者下方显示赞助者。维护者编辑本仓库 `main` 分支的 [community/sponsors.json](../community/sponsors.json) 即可更新名单，无需重新打包程序。当前正式名单为空；[sponsors.example.json](../community/sponsors.example.json) 仅用于说明格式，不会被应用读取。

## 添加一位支持者

1. 在 GitHub 打开 `community/sponsors.json`，点击编辑。
2. 在 `sponsors` 数组中增加一项。使用稳定且不重复的 `id`，例如 `supporter-001`；填写本人同意公开的昵称和社交链接。
3. 把 `updatedAt` 改成本次更新时间，使用 UTC ISO 时间，例如 `2026-10-22T08:00:00Z`（北京时间 16:00）。
4. 提交到 `main`。维护者可直接提交；社区修改通过 Fork/PR 交由维护者审阅合并。

```json
{
  "schemaVersion": 1,
  "updatedAt": "2026-10-22T08:00:00Z",
  "sponsors": [
    {
      "id": "supporter-001",
      "name": "已同意公开的昵称",
      "note": "谢谢你的支持",
      "links": [{"label": "Bilibili", "url": "https://space.bilibili.com/13551697"}],
      "order": 10
    },
    {"id": "anonymous-001", "anonymous": true, "order": 20}
  ]
}
```

这是填写示例，不代表示例帐号实际赞助。`order` 较小的先显示；相同顺序沿用文件中的排列。没有 `order` 的排在已指定顺序之后。最多 300 项、昵称 80 字符、留言 180 字符、每人最多 5 个 HTTPS 链接，链接名称最多 24 字符。不要填写收款凭证、订单号、真实姓名或未获同意的联系方式。

匿名项只显示“匿名支持者”；即使误填昵称、头像、留言或链接，客户端也不会展示这些字段。不过 JSON 和 Git 历史本身公开，匿名项请只填写示例中所示字段。

## 添加头像

将得到授权的 PNG/JPG/JPEG/WebP 上传至 `community/avatars/`，例如 `community/avatars/supporter-001.png`，然后在该人的记录中添加：

```json
"avatar": "avatars/supporter-001.png"
```

头像文件名只使用英文字母、数字、短横线或下划线。图片不超过 1 MiB。客户端仅从本仓库读取这类相对路径，不读取任意网站或本地路径。头像失败时显示昵称首字或匿名符号，不影响名单；替换头像后同步更新 `updatedAt`。

## 刷新与离线行为

- 进入页面先显示本地缓存，再检查是否需要同步；页面打开期间每 5 分钟检查一次，也可点击“刷新赞助者”。
- 成功同步后的自动检查间隔为 5 分钟；手动刷新至少间隔 10 秒，避免连续点击造成重复请求。
- 使用公开 JSON 原文与 ETag 条件请求；GitHub/CDN 缓存和网络可能延迟生效，这不是秒级推送。
- 名单保存于用户已选择的资料库 `cache/community-sponsors.json`，头像也在同一缓存目录；迁移资料库会携带这些缓存。
- 普通资料库备份用于素材标注与素材封面，赞助者缓存不作为个人资料备份；在新位置恢复后可重新联网获取。断网时若该位置已有缓存，继续显示缓存。
- 关闭全局联网后不请求名单或头像，并取消进行中的任务。无效 JSON、未知格式、网页错误、超限内容或头像失败都不会清空原有有效名单。
- 网络请求不发送素材名称、资料库路径、支付记录或账户凭证，客户端不内置 GitHub 密钥。

当前为维护者人工更新名单，不对接收款账户，不自动验证到账。以后若采用具有官方 API/Webhook 的赞助平台，可由独立服务把经同意的公开信息同步到同一 JSON，无需更改客户端显示结构。

## 仓库管理与回退

仓库保持公开，只有维护者拥有直接更新正式内容的权限，社区继续通过 Fork/PR 参与。主分支规则允许维护者直接提交，不要求维护者给自己提 PR。

如需撤回名单修改，在 GitHub 查看该文件历史并恢复上一份 JSON，更新 `updatedAt` 后提交。若名单格式有误，应用继续保留上一份缓存，可先修正再点刷新。

如需撤回主分支规则，在 Settings → Rules → Rulesets 中禁用本次的 `Owner controls main` 规则；不会删除代码或改变仓库公开状态。
