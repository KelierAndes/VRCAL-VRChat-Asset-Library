## 核查结果

- 千问：官方视觉接口支持图片与文字输入，可输出结构化信息；本轮已接入百炼北京文本接口，不代表已测得它的分类准确率高于其他模型。
- Kimi：官方视觉接口支持图片理解和 JSON Mode；本轮已接入中国文本接口。模型能力必须按实际选定模型核对，不把聊天网页订阅视作已取得 API 调用额度。
- DeepSeek：当前官方 Vision 文档明确列出支持图文输入的模型，可以纳入同一套样本评测；不能沿用“所有 DeepSeek 模型都仅支持文字”的旧判断。
- 接口模型、地域与价格会变化；实施时读取对应平台当前配置，不能将模型名、免费额度或价格承诺为永久可用。

上述视觉能力是供应商能力核查；**本轮三个接入都只发送文字，没有图像上传开关或视觉分类实现**。

## 已有接入位置

- `src/main/hints.ts` 继续保留本商品最细官方类目优先；`displayCategory` 优先使用人工分类，AI 不覆盖这两层依据。
- `src/shared/ai-contracts.ts` 定义设置、有限输出词表、建议、来源和错误契约；主进程服务通过已有 IPC／preload 接入界面。
- `src/main/ai-service.ts`、`ai-settings.ts`、`ai-privacy.ts`、`ai-schemas.ts` 负责官方域名请求、密钥加密、输入过滤、严格输出校验、限额及缓存。
- `src/main/ai-classification-queue.ts` 负责串行队列和处理指纹；独立建议保存在资料库 `ai-cache.json`，不混入在线商品字段或 `manual.tags`。
- `src/renderer/ai-tools.tsx` 提供设置、队列状态与素材详情建议。接受建议时沿用人工标签接口；后台刷新不会自行重新加入用户已删除的人工标签。

## 已实现的自动处理与边界

1. 一次配置并启用后，每 30 秒处理一项符合条件的服装。只处理未隐藏、未缺失、未回收的素材，不处理工程或人工归到其他类别的素材。
2. 使用明确匹配的公开 BOOTH 商品资料。人工确认或具有同商品来源和明确规则证据的自动匹配均可进入；歧义候选不自动发送。上传白名单只有公开标题、说明、标签及文件名末段，不上传封面或本地图片。
3. 使用有限类型／风格词表及严格结构校验，不采用自动接受为人工标签的规则。置信度是模型输出，不等于测得准确率；内容不清楚时可返回不确定或空标签。
4. AI 仅返回受校验的数据，不执行返回的指令、网址或代码，不获得桌面、文件修改、账号 Cookie 或下载权限。
5. 主界面只展示进度与结果，不逐条弹确认窗口。关闭 AI／联网会暂停并取消处理；可以明确重试。当前没有“一键撤回全部 AI 历史”的入口，已有建议与人工接受标签分别保留。
6. 成功与失败都保存处理指纹，重启不反复发送未变内容；公开输入或模型等改变后重新评估。普通备注变更不触发请求。达到额度或指纹容量上限时暂停。
7. 密钥只在应用内输入、系统加密保存。界面显示每日调用次数与次数上限，不提供实际 token 账单或金额预算；实际账单由服务商查询。普通备份排除 AI 文件，接受为人工标签的内容正常备份。

## 已采用的首次配置与费用方式

本轮采用 **用户提供自己的 API Key、本机直接访问所选官方 API**。服务默认关闭，用户在设置中选择服务商、用途和次数上限，了解范围与费用后启用。同一服务商的分类和诊断共用密钥，不需要为每个功能重复填写。

没有建立项目统一收费服务、共用密钥或离线大模型运行环境。当前缺少真实服务商密钥，因此没有进行付费测试，也不能宣称已测得真实准确率与成本。此记录描述本地实现，不是公开发布公告。
